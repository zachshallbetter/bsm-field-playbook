# BSM Field Playbook

Operational guides, checklists, and SOPs for aviation operators, restaurant owners, and skydiving dropzones — free to use, adapt, and improve.

Built and maintained by [Blue Skies Matter](https://www.blueskiesmatter.com) based on real work with real operators across the Pacific Northwest and beyond.

---

## Why This Exists

The businesses we work with — flight schools, FBOs, restaurants, dropzones — are run by people who are exceptional at what they do and under-resourced when it comes to the operational infrastructure around it. They're flying planes and flipping pancakes, not writing process documentation.

Over the years, we've built a lot of that infrastructure quietly, for individual clients: playbooks for onboarding staff, checklists for opening and closing, integration guides for POS systems and manifest software, SOPs that actually get followed because they were written by people who've worked the floor.

The BSM Field Playbook puts those resources in one place and makes them free. A dropzone in Idaho and a charter operation in Arizona shouldn't have to reinvent the same wheel.

## How to Use These

Every document is in Markdown — readable in GitHub, easily converted to PDF, Word, or Google Docs.

**Download a single file:**
```bash
curl -O https://raw.githubusercontent.com/zachshallbetter/bsm-field-playbook/main/aviation/aircraft-turnaround-checklist.md
```

**Clone the whole repo:**
```bash
git clone https://github.com/zachshallbetter/bsm-field-playbook.git
```

**Fork and adapt:** Hit the Fork button, make it yours. Change the language, add your logo, remove steps that don't apply. That's the point.

## Contributing

If you work in aviation, food service, or adventure sports and have a resource worth sharing, we want it here.

### Ways to Contribute

1. **Open a pull request** — add or improve a document directly
2. **Open an issue** — request a resource, flag an error, or suggest an improvement
3. **Send it to us** — [contact form](https://www.blueskiesmatter.com/contact?venture=oss) if you prefer not to use GitHub

### Contribution Standards

- Write for the person doing the job, not for the person writing the manual
- Use plain language — if a word has a simpler version, use it
- Checklists should be actionable: "Refrigeration temp ≤38°F" not "Check refrigeration"
- Include a brief header noting who the document is for and when to use it
- Add a note at the bottom if the document is jurisdiction-specific or requires adaptation

All contributions are reviewed before merging. We'll work with you if anything needs adjustment.

## Format Guidelines

Documents follow this general structure:

```markdown
# Document Title

**For:** Who uses this  
**When:** When to use it  
**Duration:** (optional) How long it takes

---

## Section

- [ ] Checkbox item with specific, measurable action
- [ ] Another item

---

*Adaptation note at the bottom if relevant.*
```

## What This Is Not

- **Not regulatory guidance.** Nothing here replaces FAA regulations, state health codes, USPA guidelines, or any other governing rules for your operation. Always verify against the applicable standards for your jurisdiction and operation type.
- **Not legal advice.** Don't use these documents as legal protection without your own review.
- **Not one-size-fits-all.** Every operation is different. Use these as a starting point, not a final answer.
